# AI・作戦指示の実装記録

更新日：2026-09-06

[設計方針](ai-strategy-design.md)に基づき、既存の3D将棋へブラウザ内で動くAIを追加した。先手・後手どちらも、対局途中から個別にAIへ任せられる。

## 操作

- 右側の「AIへの作戦指示」で、任せたい陣営の「AI開始」を押す。手番でなければ次の手番を待つ。
- 両軍で開始するとAI同士の観戦になる。「AI停止」でその陣営を手動へ戻し、「両軍を停止」で両方止める。
- 「AIのテンポ」で速い（約1秒）・標準（約3秒）・じっくり（約5秒）を選ぶ。初期値は約3秒に1手。速い設定は探索量を減らす。戦闘中も思考・着手を進め、「戦闘演出」「効果音」を個別に切り替えられる。
- 戦法はおまかせ・居飛車・四間飛車・中飛車。作戦はおまかせ・攻勢・守備・反撃狙い。途中変更は現在の未確定の思考から反映する。
- 停止しても確定済みの棋譜は維持する。開始・停止・指示・棋譜は自動保存し、再読み込み後も引き継ぐ。初回と旧保存は両軍手動。
- 人間対AIで戻すと直前の人間の判断位置へ戻る。両軍AIの戻す操作は両軍を停止し、一手戻す。戻した結果がAIの手番になる場合も停止して指し直しを防ぐ。
- 読み込み・応答・合法性の問題では盤面を進めず再試行を表示する。AI停止で手動に戻れる。

## 採用エンジンと探索

やねうら王のWASM移植 [yaneuraou-suisho-petite](https://github.com/usumerican/yaneuraou-suisho-petite/tree/4568f76268128a65c5936d15a2188c8f64f71847) の `nosimd` を固定して同梱した。USIの自己識別は `YaneuraOu NNUE KP256 7.63 32WASM TOURNAMENT`、評価関数は内蔵のSuishoPetite20211123。エンジンへの通信や盤面の外部送信は行わず、AI起動時に同じ配信元から必要ファイルを読む。

| 項目 | 実装値 |
| --- | --- |
| 探索スレッド／ハッシュ | Threads 1／USI_Hash 16MiB。WASMの総メモリ量を16MiBに制限する意味ではない |
| 通常探索 | MultiPV最大5手。標準は50,000ノード／1,500ms、速いは12,000ノード／350ms、じっくりは80,000ノード／2,200ms |
| 定跡候補の追加探索 | 合法な候補にsearchmovesを限定し、6,000ノード、450ms |
| 作戦を考慮する候補 | 同じ完了深さの確定値で、最良cpとの差が110以内。王手中と全おまかせは差0 |
| 作戦補正 | 駒の働き、相手玉への圧力、自玉の守り、往復・反復の抑制。合計±100以内 |
| 表示上の最短思考間隔 | 標準3,000ms、速い1,000ms、じっくり5,000ms。約3秒の戦闘部分と前後の演出を含む合計4.2秒とは独立 |
| 異常時 | 初期化20秒、探索の応答期限、停止900msの監視。応答しないWorkerを破棄し再試行で再生成 |

候補比較では異なる探索深さや上下限だけのスコアを混在させない。詰み評価は通常のcpと分離する。有限探索と簡単な局面特徴を使う初期実装であり、指定戦法の実現・事故の完全回避・何級相当の棋力を保証しない。

## 戦法

`scripts/build-openings.mjs`で、独自の短い序盤手順の組み合わせから197の正規化局面を生成する。先後を反転して同じ索引を使い、実際の合法手と照合する。棋譜の手数だけで強制再生する方式ではない。外部の定跡データは追加していない。

定跡を外れたら、序盤の飛車の横移動が合法な場合に限定して移行を試みる。王手、持ち駒の発生、32手以降、飛車の不在・成り、移行を6回試みた場合などは移行を中断し、画面に作戦指示を優先する旨を表示する。多手を要する高度な囲い直しは未実装。

## 制御・保存・演出

`GameController`が依頼を管理し、AIも人間も`Match.play()`でのみ着手を確定する。SFENと全着手履歴を渡し、千日手に必要な履歴を落とさない。`gameId / positionRevision / policyRevision / requestId / side`を照合して古い回答を破棄する。Worker内では停止後の旧bestmoveを回収してから次の探索を開始する。AIの投了は終局として扱い、未対応の宣言勝ちは受理しない。

保存キーは既存の`aether-shogi-v1`を維持し、内容の`version`を2にした。先後の設定、初期設定、指示変更の時点・連番・変更前後を棋譜とは別に保存する。戻す操作で指示履歴も戻す。Workerや依頼IDは保存せず、復元時に新しく生成する。

着手を確定したら演出の終了を待たずに次のAI思考・人間操作を許可する。別の部隊は並行して移動し、同じ部隊への次の指示・取り返しでは旧演出を短縮する。捕獲された表示は選択不能な残像として分離し、直後の持ち駒投入と混同しない。2026-09-06に全兵種の戦闘を追加し、移動・戦闘をPC最大6件・スマホ最大4件、一時演出全体を最大12件、粒子を192要素以内へ調整した。戻す・リセット・復元では旧世代の表示と音を無効化する。詳細は[戦闘演出の実装記録](combat-implementation.md)。

## 配信・ソース

WASMは1,425,683 bytes。`dist/ai/vendor/manifest.json`に配布元リビジョン、容量、SHA-256を記録し、`npm run build`で照合する。画面の「AIについて」からGPLv3本文、対応ソースZIP、ビルド手順へ到達できる。エンジン・内蔵評価データのソースアーカイブと移植側ビルドファイルを同梱した。採用バイナリをこの環境で再ビルドしたという意味ではない。詳細は [SOURCE.md](../dist/ai/vendor/SOURCE.md)。

`npm run dev`はCOOP・COEPヘッダーとWASMのMIME型を設定する。静的ホスト用の`dist/_headers`も同梱。ヘッダーのないlocalhost／HTTPSでは、最初のAI起動時に専用Service Workerで同じ配信元の応答へヘッダーを補い、一度だけ再読み込みする。対局とAI設定を先に保存する。オフラインキャッシュは作らず、別アプリのService Workerは置き換えない。準備失敗時の無限再読み込みを防ぐ。対応ブラウザ・安全なオリジンが必要。

## 検証範囲

`npm test`でSFEN・USI・全履歴、先後の開始停止、旧回答、連続指示変更、独立した演出、戻す・復元・投了・異常復旧、全定跡の合法性、候補比較を確認する。作戦差の単体テストは評価を揃えた検証局面を使い、実対局での棋力差を主張するものではない。

`npm run test:web`で実物WASMの先後対局、AI同士の連続着手と並行移動、指示変更、途中停止、履歴再生、保存復元、読み込み失敗からの再試行、打ちによる詰み、後手の強制成りによる詰み、スマホ幅での開始停止を確認する。ヘッダーを持たないサーバーでの初回準備と進行中局面の維持、演出中の取り返し・即時投入・再移動・戻す・リセットも対象。

結果件数とPCの描画計測は [実装・検証記録](implementation-report.md)、[AI思考中の計測](verification/ai-performance.json)に記録する。スマホはChromeのタッチ・画面幅エミュレーションまで。実機スマホ、Safari、長時間の多数対局による棋力・作戦品質の統計的評価は未実施。
