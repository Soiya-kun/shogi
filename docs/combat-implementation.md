# 部隊戦闘の実装記録

更新日：2026-09-06

[採用設計](capture-animation-design.md)に基づき、全8兵種と成り飛車の龍へ戦闘演出を追加した。将棋の着手は即座に確定し、戦闘が終わる前に次のAI思考・着手・人間操作へ進める。遠景は軽量モデルの部位を動かし、接近すると既存の詳細な甲冑・武器を使う。

## 画面からの操作

「AIのテンポ」「戦闘演出」「効果音」を右側の操作欄へ追加した。標準のAIは約3秒に1手。両軍のAIを開始すると、約4.2秒の演出が終わる前に次の着手が進む。カメラは現在の位置を維持し、ドラッグ・ズームを妨げない。戦闘演出をOFFにすると進行中の演出を破棄して最新局面へ即座に同期する。

| テンポ | 最短思考間隔 | 探索上限 |
| --- | ---: | --- |
| 速い（約1秒） | 1,000ms | 12,000ノード／350ms |
| 標準（約3秒） | 3,000ms | 50,000ノード／1,500ms |
| じっくり（約5秒） | 5,000ms | 80,000ノード／2,200ms |

速い設定では探索量を減らす。実際の間隔は探索・定跡候補の比較・端末負荷によって延びる。演出時間を伸縮させる設定ではなく、戦闘完了を待つ条件にも使わない。変更時に進行中の探索をやり直さず、次の依頼から新しい探索上限を使う。

効果音は初期OFF。ONにするとブラウザ内で合成した打撃・斬撃・矢・術・炎の短い音を鳴らす。端末の「動きを減らす」が有効な場合は演出を省略する。表示・音・テンポは`aether-presentation-v1`へ保存し、棋譜の巻き戻しから独立させる。

## 各兵種

通常は接近0.6秒、戦闘3秒、進駐・整列0.6秒、合計4.2秒。敵側も武器を構えて応戦し、槍の牽制、射撃、斬撃などを経て、前列から倒れる。敵の旗も傾いて消える。流血は使わず、演出中の勝敗抽選は行わない。確定した将棋の着手どおり、取る側が勝って進駐する。

| 部隊 | 実装した演出 | 画面 |
| --- | --- | --- |
| 歩・足軽 | 槍を水平に構え、前列から少しずらして踏み込み・槍突き | [足軽](verification/combat-P.png) |
| 香・長槍足軽 | 長槍を下ろして直線突撃。足元に土煙 | [長槍](verification/combat-L.png) |
| 桂・騎馬隊長と弓足軽 | 隊長が太刀を掲げる。5人の弓足軽が構え、各射手から矢が弧を描いて飛ぶ | [弓](verification/combat-N.png) |
| 銀・重装武者 | 両腕で太刀を振り上げ、重く踏み込みながら振り下ろす | [重装武者](verification/combat-S.png) |
| 金・旗本 | 中央が牽制し、左右が時間を合わせて槍を突く | [旗本](verification/combat-G.png) |
| 角・陰陽師 | 札を放ち、敵の足元に円環と符を展開。護衛侍が斬り込み、陰陽師が続く | [符術](verification/combat-B.png) |
| 飛・騎馬武者 | 馬で突撃しながら槍を構え、土煙を上げる | [騎馬](verification/combat-R.png) |
| 龍・成り飛車 | 降下し、前列の龍の口元から炎を放つ。乗り手も槍を構え、進駐時に浮上 | [龍](verification/combat-D.png) |

成り駒は元兵種の攻撃を使い、装飾を維持する。成る着手では元の姿で攻撃し、演出終了時に馬から龍への乗り替えなどを反映する。論理上の成りと旗の表示は着手時点で確定する。

## 対局と表示の分離

- `GameController.commit()`は`Match.play()`で合法手を確定し、その直後に次の探索を開始する。演出のPromiseは待たない。例外・省略・中断でも棋譜を変更しない。
- `battlefield.js`は確定済みイベントを受け、対局ID・局面更新番号・イベントID・表示の世代・部隊ID・着手前の兵種と陣営・捕獲対象を保持する。元の駒オブジェクトへの可変参照を使わない。
- 別部隊の演出は継続する。同じ部隊の再移動や取り返しでは、その瞬間の描画位置を引き継いで旧演出を中断する。取り返しの攻撃先も相手が実際に描画されている位置を使い、最後は論理上の到着マスへ進駐する。旧完了処理が新しい移動先を書き戻すことはない。
- 捕獲部隊は論理局面から即座に除き、選択不能の残像として残す。持ち駒から再投入した部隊は同じ部隊IDでも別の表示世代・オブジェクトを持ち、旧残像の削除で消えない。
- 生きている部隊の旗は常に最新の到着マスに置く。移動中の空中モデルと残像は駒選択の対象から外す。合法手・王手・棋譜・持ち駒は最新局面を使う。
- 戻す・リセット・復元・演出OFFは表示世代全体を無効化し、残像・粒子・音を解除する。復元より古いイベントを再生しない。終局とAI停止は即時に反映し、最後の戦闘は表示だけ継続できる。

## 負荷の上限

PCは移動・戦闘合わせて最大6件、スマホ幅は最大4件。超過時は最も古い表示を到着状態へ短縮する。捕獲残像も同じ件数以内。一時的な昇格の光を含む演出は合計12件以内にする。

矢・札・術式・土煙・火花・炎は固定のインスタンス描画にまとめ、合計192要素・6描画バッチ以内。音は同時4件・最短70ms間隔で、各戦闘の中断時にも止める。各粒子や攻撃にタイマーを作らず、共通フレーム処理で経過時間から状態を計算する。確認用の履歴も直近48件まで。

実物WASMの速い設定で12手を進め、最大3戦闘・4部隊の同時動作、52要素、145描画呼び出し、461,413三角形を記録した。標準設定では約3秒の着手間隔と、次の着手時に前の戦闘が続くことを確認した。スマホ幅の上限確認も行った。これらは検証用の接触局面の値であり、実機スマホの性能測定ではない。

## 検証と編集箇所

ブラウザでは全兵種、後手、成り後の龍、成り桂・角、接近表示、敵の転倒、最新マスの選択、実物AIの並行戦闘、同じ棋譜の演出OFF再生、即時の再投入と世代分離、同部隊の再移動、取り返し、戻す、リセット、再読み込み、終局、スマホのタッチと動きを減らす設定を確認する。

`npm test`は27件、`npm run test:web`は追加6件を含む全25件が成功し、`npm run build`のアセット検証も通過した。標準AIの着手間隔は計測で約3.003秒となり、その時点で前の戦闘も継続していた。
