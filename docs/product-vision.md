# 将棋アプリの構想と制作方針

更新日：2026-09-06

この文書は、会話で共有した構想と実装の現在地を引き継ぐための記録です。2026-09-05に「一通りこなしきる」という依頼を受け、草原フィールド、8兵種のBlenderモデル、WebへのGLB取り込み、地形に沿うマス目と操作・演出を実装し、ローカルで検証しました。その後の「一駒を一部隊にする・スケールを広げる・地形をリアルにする」という計画も実装しました。詳しくは[部隊化・広域フィールド](squad-scale.md)を参照してください。

## 1. 作りたいもの

**将棋そのもののルールで遊べる、兵士と自然のフィールドを使った3DのWebゲーム。**

ユーザーの希望は、ファイアーエムブレムのような戦場と兵士のあるゲームの雰囲気を、将棋の見た目に取り入れることです。現在の「盤の上に駒が並ぶ」表現から、野原や丘の上に兵士が並ぶ表現へ進めます。

### 明示された希望

- ゲームのルールは将棋そのものにする。
- 駒を6〜12人の部隊として表現し、今風のゲームらしい見た目にする。
- フィールドを盤ではなく、野原や丘などの地形にする。
- 地形に線で区切りを入れ、マスが分かるようにする。
- Blenderで細かく作り込んだモデルやフィールドをWebに載せたい。
- Workで作成したデモを、このリポジトリで管理する。
- ローカルのBlenderをMCPで操作できるようにする。

参照作品の名前は雰囲気を共有するためのものです。今回は、明るい草原と緩やかな丘、銀色の鎧、青・赤の布を使うオリジナル造形を採用しました。

## 2. 現在のデモ

名称は「AETHER SHOGI — 蒼穹の盤上」。Workの「将棋ゲーム設計」で作成したデモを取り込み済みです。

- 公開デモ：https://aether-shogi.seiyaito.chatgpt.site
- 管理リポジトリ：https://github.com/Soiya-kun/shogi
- 元ソースコミット：`d73727857816ceba91d9da95ca0e307f547f4573`
- 取り込み日：2026-09-05

### 現在の表現・機能

- Blender製の草原・丘・小道・木・岩・下草・周辺の石積みの遺構。地面に直接9×9の区切り線を描画。
- 青と赤の40部隊・392人を使う、同一端末での2人対局。先手・後手それぞれを任意の時点でAIへ委任でき、AI同士の観戦も可能。
- 戦法4種類と作戦4種類。指示変更、AI停止による手動への復帰、保存復元。思考と移動演出は独立して進む。
- Blenderで制作した8兵種のGLBモデル。桂馬の騎馬隊長と弓足軽、銀の大鎧をまとった重装武者、飛車の騎馬武者。飛車は成ると翼のない東洋の龍に乗り替わって浮遊する。陣営色と成り時の金装飾にも対応。
- 移動、捕獲、成り、持ち駒の投入、合法手と王手の判定。
- 全兵種の戦闘演出と効果音。攻撃中も次のAI思考・着手を進め、別部隊が並行して動く。再移動・取り返し・捕獲直後の打ち・巻き戻しにも対応。テンポ・演出・音を画面で切り替える。[実装記録](combat-implementation.md)。
- 二歩、行き所のない駒、打ち歩詰めなどの禁止手への対応。
- 千日手・連続王手の千日手判定。
- 移動先表示、左ドラッグで平行移動、右ドラッグで視点回転、カーソル位置を中心とした拡大縮小、俯瞰、全景・部隊への接近、駒名表示、一手戻す、対局リセット。
- ブラウザのlocalStorageへの自動保存。

ルール・対局・AI制御・描画と実物WASMを検証しています。検証範囲と最新の結果は[実装・検証記録](implementation-report.md)、AIの採用版と動作は[AI実装記録](ai-implementation.md)を参照してください。

## 3. フィールドの方向性

### 目指す見た目

盤を置くのではなく、草原や丘そのものを対局フィールドとして見せます。その地面に9×9の区切り線を重ね、兵士の位置と移動先を読み取れるようにします。

### 実装した作り方

- 草原、緩やかな丘、道、岩、木などの地形・装飾をBlenderで制作する。
- フィールドをGLBとして書き出し、Three.jsへ読み込む。
- マス目の線、選択表示、移動先・攻撃対象のハイライトはThree.js側で描画する。
- 各マスの地面の高さに合わせて兵士と表示を配置する。
- 対局エリア内は緩やかな起伏にし、周辺に森や崖などを配置する。

対局範囲は108m四方、マス中央の高低差は約4.86m。1マス12m、周辺地形は480m四方です。草・土・岩の実写素材を使い、木や大きな岩は対局範囲の外に配置しました。形状はBlender、材質混合はWeb側で編集できます。

### 将棋との対応

内部の盤面は引き続き9×9として管理します。地形の高さを演出として扱い、移動力、防御力、射程などの追加ルールは設けない方針です。見た目を変えても将棋の合法手や手番管理を維持します。

## 4. 兵士モデルの方向性

Blenderで作り込んだ兵士をGLBで取り込み、現在の基本形状によるモデルと差し替えることができます。

以下の表現を実装しました。アニメーションはBlenderの部位階層をThree.jsから動かす方式で、リグやGLBのアニメーションクリップは使っていません。

- 兵種ごとの鎧、武器、顔、服の作り込み。
- 待機、移動、攻撃、倒れるアニメーション。
- 成りによる上位兵種への見た目の変更や演出。
- 先手・後手を色や装備で見分けられる表現。

今回はフィールドを先に制作し、歩を含む全8兵種を同じ造形ルールで用意して40部隊・392人を配置しました。

2026-09-06に全兵士を日本の侍系へ変更しました。歩は足軽、香は長槍足軽、桂は騎馬武者と弓足軽、銀は大鎧の重装武者、金は旗本、角は陰陽師と護衛侍、王は大将と旗本。飛車は通常時が馬に乗る騎馬武者、成り後が長い胴・角・ひげを持つ東洋の龍に乗る龍武者です。部隊旗は三つ丸紋の幟に統一しました。人数・隊形・将棋ルールは維持します。

## 5. 技術構成とアセットの扱い

現在はビルド不要のHTML・JavaScript構成です。既存のルールと対局処理を活かし、表示を段階的に変更する想定です。

| 担当 | 現在の実装・今後の役割 |
| --- | --- |
| 将棋ルール | `dist/rules.mjs`。合法手、成り、王手、持ち駒など |
| 対局管理 | `dist/match.mjs`。盤面、手番、記録、合法手検証、終局判定。`dist/app.js`が画面と保存を接続 |
| AIと指示 | `dist/game-controller.mjs`と`dist/ai/`。先後別の担当、指示、履歴、Worker＋WASM探索、古い回答の排除 |
| 3D表示・操作 | `dist/battlefield.js`と同梱Three.js。`dist/terrain.mjs`で実際のGLB三角形から高さを取得 |
| 画面 | `dist/index.html`、`dist/style.css` |
| Blender | `assets/blender/aether-assets.blend`。フィールドと兵士の編集用ソース |
| GLB | `dist/assets/meadow.glb`、`army.glb`を同梱GLTFLoaderで読込 |

### Web向けに考慮すること

- Blender上のすべての材質・効果が、そのままGLBに再現されるとは限らない。必要に応じてテクスチャへのベイクや調整を行う。
- 将棋では初期配置で40部隊・392人を表示するため、ポリゴン数、テクスチャ、影、描画回数などを調整する。
- 地形・モデルの縮尺、原点、向きと、マス座標との対応を定める。
- 地形に線やハイライトが埋まる、ちらつく、兵士が浮くなどの問題を確認する。
- PCブラウザを主対象とし、スマホ縦画面・タッチ入力にも対応。PC110万三角形・500描画呼び出し未満、素材合計34MiB未満を目安とする。実機スマホの性能確認は未実施。

編集用の`.blend`を`assets/blender/`、配信用の`.glb`を`dist/assets/`に分け、通常のGitで管理しています。手作業の編集を保持した再書き出しと、初期造形の再生成を別スクリプトにしました。詳しくは[Blender編集手順](../assets/blender/README.md)を参照してください。

## 6. Blender MCPの現在地

2026-09-05時点のローカル環境で、以下を実施済みです。

- Blender 5.2.1 LTSを確認。
- `ahujasid/blender-mcp` 1.9.1のサーバーを専用Python仮想環境へインストール。
- Blenderアドオンを有効化し、ユーザー設定を保存。
- Codexのユーザー設定に`blender` MCPサーバーを登録。
- 接続先は`127.0.0.1:9876`。サーバー側のテレメトリを無効化。
- PythonのMCPクライアントで28個のツールを取得。
- `get_scene_info`でCube・Camera・Lightの取得に成功。

今回の作業でCodexの直接Blender MCPツールが利用可能になりました。`get_scene_info`で接続を確認し、`execute_blender_code`で作成した`.blend`を開いてシーンを操作できています。制作・再生成は再現性のためBlenderのバックグラウンド実行スクリプトを使っています。

Blenderを開き、アドオンのサーバーが動いている状態で操作します。この設定はローカルPC用で、将棋アプリのWeb実行時にMCPは不要です。

## 8. 開発と公開

- 今後のソース管理先は本リポジトリ。
- ローカル起動は`npm run dev`。`npm ci`の後、`npm test`・`npm run build`・`npm run test:web`で検証。
- `dist/`は現状の編集対象ソース兼配信ファイル。生成物扱いで削除しない。
- 元デモのSites設定を保持しているが、GitHubへのpushだけでは公開デモは更新されない。
- 今回はリポジトリ内の実装・検証までを完了。既存Sitesへの公開更新は行っていない。公開デモのURLは元デモを指す。

起動方法などの基本情報は[README](../README.md)を参照してください。
