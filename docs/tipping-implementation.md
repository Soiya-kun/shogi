# 投げ銭の実装と有効化

2026-09-09。本番設定を有効化。ユーザーからStripe開通完了の申告を受け、300円・500円・1,000円の本番Payment Linksを作成した。公開名義は伊藤誠也、問い合わせは`djmaajtj@gmail.com`。住所・電話は請求時開示とし、ユーザーが個別対応可能と確認済み。

## 実装内容

- 既存の終局状態を観測し、手動・AIどちらの対局も終了後に応援モーダルを1回表示する。
- 最低1.5秒は結果を見せ、最後の着手と勝敗演出が終わるまで待つ。異常時の待機上限は16秒。別モーダルや非表示タブではさらに待つ。
- 300円・500円・1,000円を選択し、対応するStripeの外部決済ページへ進む。初期選択はなし。
- ×、Esc、「今回は閉じる」で支払いなしに盤面へ戻る。設定と終局パネルから再表示できる。
- 表示した対局をlocalStorageの対局データ内に保存。一手戻し・再終局・再読込では自動再表示せず、新しい対局では表示する。決済済みの情報としては使わない。
- ゲームの応援UIは日本語・英語に対応。案内ページは現時点では日本語。
- 特商法表記、プライバシー、応援・返金ページを追加。金額・追加費用・返金条件と請求時開示の表記を確定済み。

## ローカルで確認

```powershell
npm run dev
```

`http://127.0.0.1:5173/?support-preview=1`を開き、歯車→「ゲームを応援する」で表示を確認する。プレビューを有効にした対局では終局後にも自動表示する。金額は選べるが決済リンクは生成しないため、支払いは発生しない。

`support-preview=1`はlocalhost・127.0.0.1・IPv6ループバック限定。本番ドメインに付けても機能を有効化できない。プレビューの表示済み状態も保存されるので、同一対局の終局を繰り返しても再表示しない。

## 設定手順と決済試験の範囲

`dist/support-config.mjs`が公開用設定。秘密鍵は不要。

1. Stripe担当者の回答を確認する。利用できるモデル・追加条件を記録し、`providerApproved`をtrueにする。
2. 運営者の公開名義、住所、電話、問い合わせメールを`operator`へ入力する。住所・電話の請求時開示を採用する場合はStripeの条件を確認し、実際に開示対応できる文言を入れる。
3. `legal.html`の金額・追加費用と`support-terms.html`の返金条件に残る「予定」「受付開始前」の文案を確定し、プライバシーの内容も確認する。完了後に`disclosuresReviewed`をtrueにする。
4. 300円・500円・1,000円の単発Payment Linksを作成。数量変更は無効にし、税の設定を含め請求総額と案内金額を一致させる。完了画面・レシート・返金設定を確認する。
5. 各価格の`url`に本番リンクを設定する。異なる価格に同じリンクを設定できないよう検証する。本番設定に`test_`リンク、外部ドメイン、クエリー付きURLは受け付けない。
6. Stripeテスト環境で成功・失敗・本人認証・キャンセルを確認する。今回のブラウザテストは決済画面へのリンク対応を確認しており、Stripeそのものの決済試験は未実施。
7. 全項目の確認後に`enabled`をtrueにし、既存のAWS配信手順で公開する。

`enabled`、承認、開示確認、運営者情報、3つのURLのどれかが欠けると受付を有効化しない。設定チェックは形式検証であり、Stripe上のリンクの金額・有効状態・審査結果を検証するものではない。

住所・電話について、[Stripeの日本向け開示ガイド](https://support.stripe.com/questions/how-to-create-and-display-a-commerce-disclosure-page?locale=ja-JP)は個人事業主の請求時開示を案内している。これは実データをサイトへ常時掲載しない方式であり、請求にも応じなくてよいという意味ではない。2026-09-09に運営者が個別の請求へ対応できると確認した。

## 停止方法

Stripe側でリンクを無効化し、`enabled: false`へ変更して再公開する。Stripe側の無効化を先に行うことで、キャッシュされたゲームや既存リンクからの受付も止められる。
